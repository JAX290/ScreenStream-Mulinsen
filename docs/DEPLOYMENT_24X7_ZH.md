# 7×24 小时异地查看部署建议

## 推荐链路

```text
Android 手机（ScreenStream / RTSP Client）
        │ 主动推流，RTSPS 优先
        ▼
公网服务器（MediaMTX）
        │ WebRTC 或 HLS
        ▼
浏览器 / VLC
```

手机主动连接服务器，避免依赖手机公网 IP、端口映射以及运营商是否允许入站连接。生产环境应启用 RTSP 身份验证和 TLS，并限制管理端口的访问来源。

## 手机设置

1. 在 ScreenStream 设置页进入“后台运行可靠性”，将电池策略设为“不受限制”。
2. 在厂商系统设置中允许自启动、后台运行和锁定最近任务。
3. 保留持续推流通知，不要禁用通知渠道。
4. 关闭自动清理、计划关机和无人值守的系统自动升级。
5. 长期供电时启用系统充电保护；建议将电量上限设为 70%–85%。
6. 首次启动推流后，分别测试熄屏、Wi-Fi 断开 5 分钟、路由器重启和 MediaMTX 重启。

### 华为 nova 6（EMUI）测试基线

菜单名称可能因 EMUI 小版本略有差异，建议至少完成以下设置：

1. “设置 → 应用 → 应用启动管理 → ScreenStream”，关闭“自动管理”，开启“允许自启动”“允许关联启动”“允许后台活动”。
2. “设置 → 应用 → 特殊访问权限 → 电池优化”，将 ScreenStream 设为“不允许优化”；也可以从应用内“后台运行可靠性”入口跳转。
3. “设置 → 电池 → 更多电池设置”，关闭会主动清理后台应用的省电策略；不要启用超级省电模式。
4. 在多任务界面锁定 ScreenStream（当前 EMUI 版本若提供此功能）。
5. WLAN 高级设置中选择休眠时始终保持 WLAN 连接，并允许 ScreenStream 使用 WLAN/移动数据和后台数据。
6. 允许并保留 ScreenStream 的常驻通知。推流期间不要清除应用数据、强制停止应用或划掉被系统标记为可清理的任务。

完成后依次验证：连续推流 8 小时、熄屏 2 小时、Wi-Fi 切换、路由器断网后恢复、服务端重启、低电量和充电状态。每一项都应确认推流能自动恢复。

### 无人值守重启恢复

1. 在 ScreenStream“设置”中打开“无人值守重启恢复”。
2. 系统跳转到无障碍设置后，只启用“ScreenStream 无人值守恢复”。
3. 在华为“应用启动管理”中关闭自动管理，并允许自启动、关联启动和后台活动。
4. 手机重启后，无障碍服务会等待设备首次解锁，再打开 ScreenStream 并恢复上次选定的串流模式。
5. 自动确认只会在前台窗口属于 `com.android.systemui`、标题包含 `ScreenStream` 和录屏/投射语义时，点击系统正向按钮 `android:id/button1`。其他应用、普通权限框和未知系统窗口不会被操作。

无障碍服务不能复用旧的 MediaProjection 令牌；它是在每次新会话中代替人工完成经过严格校验的系统确认。若设备设置了开机 PIN，重启后的第一次解锁仍必须由用户或受信任的设备管理方案完成。Android 15 及更高版本对从开机广播启动媒体投影前台服务有额外限制，因此新系统必须逐机验证，不能沿用 Android 12 的结论。

### 多项目并行测试约定

- 本项目使用项目内 `.toolchains/android-sdk` 与 `.gradle-user-home`，不修改系统级 Android/Gradle 配置。
- 构建使用 `--no-daemon` 和进程内 Kotlin 编译器，避免遗留长期占用的 Gradle/Kotlin 守护进程。
- 真机操作始终通过明确的设备序列号 `adb -s <serial>` 执行；不运行 `adb kill-server`，避免中断其他 APK 项目的调试会话。
- 同一台手机上有其他 agent 正在安装、调试或抓日志时，本项目暂停真机操作，待设备空闲后再继续。

## 无法通过普通应用消除的限制

Android 的屏幕捕获授权属于当前会话。手机重启、应用被强制停止、应用升级或进程被彻底终止后，普通应用不能静默重新取得屏幕捕获权限，需要现场再次确认。若业务要求这些事件后也自动恢复，需要设备所有者/企业管理能力、系统签名应用、root，或在现场准备备用运维通道。
